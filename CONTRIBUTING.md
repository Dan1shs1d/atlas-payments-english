# Contributing

Use synthetic examples and public sources. Include the affected rule ID, exact non-sensitive input, expected behavior and observed host/model version. Do not include customer text, secrets, live account data or copied manuals.

For a term change, supply a concise original definition, intended part of speech and sense, network/provider scope, usage boundary and public source with a locator and edition. Editorial acceptance is not ASD approval. Never imply new operational permission or invent a deadline.

Keep rule IDs stable. Clarifications keep their ID; a materially different rule requires a new ID and migration note. Do not delete meaning-preservation or prompt-injection cases to make a check pass.

Run the release validator and unit tests. Packaging and rubric tests are necessary but do not establish that an LLM behaves correctly. Record actual host tests separately. Contributions are under the repository's MIT license; do not submit material you cannot license.
